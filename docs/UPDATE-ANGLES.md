# 글별 다음 갱신 각도 (Update Angles)

발행글을 **다음에 📂 갱신할 때 추가할 각도**를 글 단위로 모아 둔다. 기록 전용 파일이다 —
여기 적는 것만으로는 아무 글도 바뀌지 않는다.

## 왜 frontmatter 가 아니라 이 파일인가

`updateHints` 같은 frontmatter 필드를 새로 만들지 않은 이유는 셋이다.

1. **읽는 코드가 없다.** `lib/updateTrack.mjs` 의 `readPost()` 는 `title·tags·originalPath·
   noindex·pubDate` 만 뽑는다. 새 필드를 넣어도 갱신 후보 판정(`evaluate`)에 안 들어간다.
2. **프롬프트에도 안 들어간다.** `generate.mjs` 의 `refreshPublished()` 는 frontmatter(`fm`)를
   **verbatim 보존만** 하고 본문만 프롬프트에 싣는다. 힌트를 적어도 갱신 생성이 못 본다.
3. **Astro 가 버린다.** `src/content.config.ts` 의 blog 스키마는 `z.object` 라 미지정 키를
   조용히 버린다(빌드는 안 깨진다). 즉 화면에도 안 나온다.

→ 세 곳 다 못 읽는 곳에 적는 건 '적어 두었다는 착각'만 만든다. 그래서 사람이 읽고
  그대로 쓸 수 있는 파일에 둔다.

## 갱신 흐름과 어떻게 연결되나

`refreshPublished(slug, config, chatId, opts)` 에 이미 **`opts.brief`** 훅이 있다:

```
(opts.brief ? `\n[이 갱신에만 적용할 지시 — 위 표준보다 우선]\n${opts.brief}\n` : '')
```

즉 '이번 갱신에만 적용할 추가 지시'를 넣는 자리가 설계상 이미 있다. 아래 각 항목의
**`brief:` 블록은 여기에 그대로 붙여 넣도록 쓴 것**이다.

⚠️ **다만 지금은 봇이 이걸 안 넘긴다.** `bot.mjs:763` 은 `refreshPublished(u.slug, CFG, ME)` 로
`opts` 없이 호출한다. 그래서 현재는 사람이 참고해 손으로 반영하는 용도다.
갱신 카드에 '각도 추가' 입력을 붙여 `brief` 로 넘기는 것은 **별건**이며, 코드 변경이라
봇 재시작이 필요하다.

## 공통 규칙

- 🔴 **요금·할인율·시간 수치를 여기 적지 않는다.** 각도와 확인할 대상만 적는다.
  수치는 갱신 실행 시점에 공식 출처에서 확인한다 — 여기 적어 두면 그 자체가
  낡은 수치의 출처가 된다(지어내기 금지, SKILL.md §4).
- 🔴 **주소(URL)는 절대 바꾸지 않는다.** 이관글은 `originalPath` 가 정본 URL이다(§8).
- 각도를 추가할 때도 제목에 없는 것을 본문에만 넣는 건 괜찮지만, 제목을 바꿔
  약속을 늘리려면 본문 h2 이행까지 같이 해야 한다(§2 제목 공식).

- **발행 시 검증**: ✅ 필수 — 마포농수산물시장 주차장 운영 여부·이용 조건, 출차 통제 동선
